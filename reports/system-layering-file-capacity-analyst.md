## Findings

No actionable defect found in the published suites. The following conclusions
are limited to their inspected contracts and current Linux oracle profiles.

### Harness execution and false-positive paths

runner.py:220-250 splits suite setup on physical newlines and ignores each
result. The file fixture is deliberately one physical line, so opening, all
three writes and the finally close execute in one program. A failed fixture
cannot satisfy the subsequent exact count/match/cursor assertions. Each test
statement is passed intact through schema.py:527-561, runner.py:475-497 and
transport.py:389-408 into one eval. runner.py:1450-1486 rejects unsuccessful
results before checking expected values. Compile/runtime errors cannot count
as value successes.

The four file cases run as wizard, close successfully acquired scan handles in
finally, and remove the long-line file after its scan; suite teardown removes
the shared three-line fixture. Fixed filenames are suite-specific. The optional
file_open requirement is legitimate: canonical src/fileio.cc:1571-1595 puts
file_open and both scan functions in the same FILE_IO registration block.
test_conformance.py:289-291 skips when that feature's builtin is absent; there
is no misspelled core-function requirement masking output-capacity assertions.

### Actual oracle producers and boundary assertions

Canonical WSL Toast src/fileio.cc:1470-1564 rewinds before both scans. Grep
consumes file_get_line until the first matching line, unless its third argument
requests all matches. Count consumes to EOF. Its file_writeline:676-710 writes
the payload followed by a newline; the new cases check both logical results
and the resulting cursor/next-line behavior. Starting count at offset 6 and
grep at offset 18 makes failure to rewind observable. Expected nested match
pairs preserve text and line numbers. The 65536-byte line case checks both
scans, line length/number, exact cursor and the following tail line rather than
only testing a scan's successful return.

Canonical src/functions.cc:527-560 refreshes the shared cache synchronously.
src/include/server.h:238 canonicalizes only positive values below the minimum;
src/include/options.h:246-256 sets default 65536 and minimum 2048.
src/server.cc:3243-3263 returns that cached value for buffered_output_length()
without arguments. The tests observe reload within the same program and cover
positive minimum, zero, negative and invalid-type default. Both save property
presence/value, restore it in finally, and reload before leaving. Their small
integer inputs are valid under all three selected numeric profiles. The
stock-64-only conversion probe and unresolved no_flush refusal are absent from
the published suites.
